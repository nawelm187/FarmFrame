# Languages in FarmFrame

English, Spanish, Portuguese (Brazil), French, German, Italian, Russian, Chinese (simplified) and Japanese. English ships with the app; every other language is one small file loaded only when chosen.

## How it works
- `src/i18n/en.ts` is the source of truth: each key is one piece of text. `es.ts`, `pt.ts`, … must have exactly the same keys (a test fails otherwise) and the same `{placeholders}`.
- Counts of things ("1 relic", "2 relics") use `tp("relCount", n)`: it picks the right plural form of each language through `Intl.PluralRules`.
- In a component: `const t = useT();` then `t("home")`, `t("savedBuilds", { n: 3 })`. Outside components, `import { t } from "./i18n"`. A key missing from a dictionary shows English, never blank.
- `LangBar` (flags at the top) calls `setLang()`, which loads the dictionary, saves the choice and sets `<html lang>`. First visit: the browser's language if we have it.
- Rules that keep translations correct: never join sentence pieces in code (word order differs); use `{placeholders}` for numbers, names and dates; plurals use `tp("name", n)` with keys `name_one` and `name_other` (Russian also `name_few` and `name_many`; Chinese and Japanese repeat the same text); join lists with `Intl.ListFormat` (see `NotFound.tsx`); keep game names as in the game; a title that is translated needs `art="English name"` so its picture is still found (`Panel`, `Unavailable`).

## Translating one more screen
1. `node scripts/i18n-audit.mjs --files` lists the hard-coded text per screen.
2. Replace each with `t("key")`, add the key to `en.ts` and to the 8 other dictionaries.
3. Add the file to `DONE` in `scripts/i18n-audit.test.mjs` once the audit shows it clean. From then on the tests stop English from coming back.
4. `npm run typecheck && npm test`.

## Search in any language
`src/lib/multilang.ts` turns words of the 9 languages into the English words the engine knows ("où farmer des crédits" becomes "where farm credits"), and the interface's own page names in every language point at the English page ("Reliquias", "Relikte", "遗物" all open Relics). Latin letters keep working with or without accents; other scripts are no longer erased. To teach it a word, add it to `CONCEPTS` and add a case to `searchMultilang.test.ts`. Item names are searched as they are in the game (English); localized item names are not indexed yet.

## Where it stands (v0.91, from `node scripts/i18n-audit.mjs`)
24 of 77 screens have no hard-coded text; 895 strings remain in 53 screens (the audit now also counts sentences written as template strings, which is why the total is higher than earlier versions reported). It still does NOT see text built in `src/lib/` or the long texts in `src/data/`. What is still English:
1. **Screens** (53): Rotations, Builds, Helminth, Profile, Advisor, Farm Plan, Roadmap, Guides, Part, Patches, Syndicates, Lore, Mastery, Planner, SearchAnswers and the smaller ones. Done so far: Home (its own text), Tracking, Fissures, Relics, Invasions, Baro, the error and 404 pages, the welcome questions, the item details labels and the status tags.
2. **Sentences made by logic** in `src/lib/` (Advisor "Why this?", Farm Now, item advice, completion notes, freshness lines, planner reasons). They must become keys with variables before they can be translated; their tests assert English text and must move with them.
3. **Long texts** in `src/data/` (guides, farming methods, Helminth, lore, syndicate wiki): prose to translate per language.
4. **Content from English sources** (patch notes, wiki summaries): stays in the source's language unless a translated source is added.

## Quality
All translations are AI-made and have not been read by native speakers. To fix one, edit the value in that language's file and run the tests. Reviewers do not need to read code: each file is `key: "text"`.
